# fm-core

Go-ядро симуляции одного футбольного матча, CLI и будущий API с Protobuf.
Текущий приоритет — этап A (CLI-first), без обязательных Docker, сети, БД или Unity.
Не реализовывать карьеру, экономику и календарь.

Общий контекст workspace: [AGENTS](../../AGENTS.md), [план](../../plan.md),
[карта docs](../../docs/README.md), [roadmap](../../docs/implementation/roadmap.md).
При отдельном клонировании эти файлы могут отсутствовать: запросить актуальные документы
для архитектурной работы; не считать архив или старые сгенерированные файлы спецификацией.

- Синхронное расчётное ядро с фиксированным Step, одним владельцем состояния и seed на матч.
- Pacing/файлы/сеть — в runner и адаптерах. Ядро не импортирует generated Protobuf.
- Все обходы, влияющие на RNG/исход, имеют стабильный порядок; входы неизменяемы.
- Физические координаты — метры, X ширина, Y высота, Z длина. Мяч имеет Vec3.
- Каждая механика проверяется CLI; события не заменяют snapshots для 3D.
- Replay входит в этап A; канонические игровые артефакты не содержат время ОС.
- Проверки после появления модуля: gofmt, go test ./..., go vet ./...;
  при конкурентности — go test -race ./... и независимость от числа workers.
- Generated-файлы не редактировать вручную; статусы roadmap менять только по проверенному DoD.

Этот каталог — отдельный Git-репозиторий; корневые docs автоматически в его коммит не попадут.
